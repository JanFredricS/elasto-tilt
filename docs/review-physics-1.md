# Physics/input independent review — cycle 1

Reviewed PLAN.md, frozen types, physics, input and both focused suites. Ran the requested Vitest command: 15/15 tests passed (Rapier initialization emits its existing deprecation warning). These tests do not establish the carry or wheel-transfer acceptance gates.

## Findings

1. **P1 — Rate clipping makes route time depend on speed and lose reversibility.** `src/physics.ts:135–142` clamps each travel-derived phase increment to platform speed, then discards all remaining displacement. A rider crossing the same distance quickly advances less time than a rider crossing slowly; retracing it at a different speed therefore does not restore the authored platform position even away from phase endpoints. At 120 Hz with a 10 m platform trajectory and timeTravel=10, a .1 m step requests .01 phase but retains only .001667, while traversing .1 m in ten .01 m steps retains .01 total. The reversal test merely observes one negative direction and cannot detect this. Preserve an explicit reversible route coordinate and separate trajectory target from collider speed limiting (or explicitly revise the mechanic contract). Add unequal-speed out/back tests away from endpoints and verify final phase and positions, plus stop behavior.

2. **P2 — Carry compensation assumes all platform movement transfers to the bicycle.** `src/physics.ts:121–132` classifies any solver contact as support and subtracts the platform's entire projected movement. A side collision, sliding wheel, or first contact with a moving platform can transfer much less displacement; subtraction then creates backwards route travel even while the bicycle is stationary or moving forward in map space. Averaging two touching platforms is similarly unrelated to actual carried movement. Use support normals relative to gravity and an explicit contact transition/slip policy; test braked and freely rolling riders on horizontal, vertical, and oblique trajectories, initial contact, detachment, side contact, and reversal. The existing time test uses a distant platform and never exercises this branch. This is a code-path correctness risk, not a claimed reproduced gameplay failure.

3. **P2 — Motion remains commanded indefinitely after samples stop and survives reset.** `src/input.ts:19,21–26,41–43` caches sensor values without a freshness timestamp; reset only clears keyboard/touch/smoothing. After a nonneutral sample, blur/hidden/reset followed by read reconstructs the old nonzero tilt immediately, and a stalled sensor commands continuing world rotation indefinitely. Clear or invalidate samples on reset/resume and expire stale samples into a neutral fallback with an honest mode message. Add tests with fake time for stopped sensor delivery and reset after nonneutral motion. Existing blur/visibility tests run only keyboard/touch, so they miss this.

4. **P1 acceptance gap — No actual ledge pivot/catch or swing transfer is tested.** `tests/physics.test.ts` checks free-flight joints, braking on a flat floor, and a swing's radius without bike contact. These cannot establish the central one-brake ledge pivot/hang/transfer mechanic. Add at least one replay using the authored lip/cradle geometry that reaches a stable wheel catch without helmet collision, pivots under gravity/brake, and successfully releases/transfers onto a swing. Check swing response to changed gravity and bounded joint error during contact. Do not claim this acceptance gate passed based on the current suite.

## Additional bounded observation

`src/input.ts:55–62` guards generation only on permission success. An older denied/rejected permission promise can overwrite a newer successful enable attempt. Apply the same generation/destroy guard before every asynchronous completion mutation and cover out-of-order resolutions if concurrent activation is possible through the UI.

The existing gravity coordinate tests, collision groups, helmet collision logic, inverted gravity scale, and equal/opposite bounded brake torques are consistent with the stated core design on inspection. Physical-device IMU feel remains unverified.
